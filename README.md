# Terraform AWS DevOps Bootcamp

## 📌 Project Overview

This project demonstrates **Infrastructure as Code (IaC)** using **Terraform** to provision and manage AWS infrastructure automatically.

Instead of manually creating resources from the AWS Management Console, Terraform is used to provision an EC2 instance, Security Group, SSH Key Pair, and automatically install Nginx using a bootstrap script.

Once deployed, the web server can be accessed directly through the EC2 Public IP / Elastic IP.

---

# 🚀 Problem Statement

Provisioning cloud infrastructure manually is:

- Time consuming
- Error prone
- Difficult to reproduce
- Not version controlled
- Hard to maintain across multiple environments

Terraform solves these problems by allowing infrastructure to be defined as code.

---

# ✅ Solution

This project automates:

- EC2 Instance Creation
- Security Group Creation
- SSH Key Pair Generation
- Nginx Installation using User Data
- Output of useful resource information
- Infrastructure cleanup using Terraform Destroy

# 📄 File Description

## provider.tf

Configures the AWS Provider and specifies the AWS Region where resources will be created.

---

## versions.tf

Defines:

- Terraform Version
- AWS Provider Version

This ensures consistency across different developer machines.

---

## variables.tf

Contains all input variables used throughout the project.

Examples:

- aws_region
- instance_type
- instance_name
- security_group_name

---

## terraform.tfvars

Stores the actual values for variables.

Example:

```
aws_region = "us-east-1"
instance_type = "t3.micro"
instance_name = "devops-bootcamp-server"
```

This keeps the Terraform code reusable.

---

## local.tf

Contains reusable local values such as common tags that can be referenced throughout the project.

---

## main.tf

Main Terraform configuration.

Creates:

- Security Group
- EC2 Instance
- User Data execution
- Tags

This is the core file responsible for provisioning infrastructure.

---

## ssh.tf

Creates:

- TLS Private Key
- AWS Key Pair
- Local PEM file

The generated key pair is attached to the EC2 instance for SSH access.

---

## scripts/install_nginx.sh

Executed automatically when the EC2 instance launches.

Responsibilities:

- Update packages
- Install Nginx
- Enable Nginx service
- Start Nginx

This is known as **bootstrapping** the server.

---

## outputs.tf

Displays useful information after deployment.

Examples:

- EC2 Public IP
- Instance ID
- Public DNS

---

## terraform.tfstate

Maintains the current state of infrastructure managed by Terraform.

Terraform compares this file with your configuration to determine what needs to be created, modified, or destroyed.

**Do not edit this file manually.**

---

## terraform.tfstate.backup

Automatic backup of the Terraform state file.

---

## tfplan

Execution plan generated using:

```
terraform plan -out=tfplan
```

Useful for reviewing infrastructure changes before applying them.

---

## .terraform.lock.hcl

Locks provider versions to ensure all developers use the same provider version.

---

## .terraform/

Stores downloaded Terraform providers and plugins.

This folder is automatically created during:

```
terraform init
```

---

## .gitignore

Prevents unnecessary or sensitive files from being committed to Git.

Typically ignores:

- .terraform/
- terraform.tfstate
- *.pem
- tfplan

# ⚙️ Terraform Workflow

Initialize Terraform

```bash
terraform init
```

Format Terraform files

```bash
terraform fmt
```

Validate configuration

```bash
terraform validate
```

Generate execution plan

```bash
terraform plan
```

Generate and save execution plan

```bash
terraform plan -out=tfplan
```

Apply infrastructure

```bash
terraform apply
```

Apply saved plan

```bash
terraform apply tfplan
```

View outputs

```bash
terraform output
```

Display current state

```bash
terraform show
```

List managed resources

```bash
terraform state list
```

Destroy infrastructure

```bash
terraform destroy
```

# 🌐 Deployment Verification

After successful deployment:

1. Open AWS Console
2. Navigate to EC2
3. Verify the instance is running
4. Copy the Public IP
5. Open:

```
http://<Public-IP>
```

If Nginx is installed successfully, the default Nginx welcome page will be displayed.
